## A-Pose 烘顶点方案正式实装（用户确认后）

- `operators/pose_operator.py`：删除「复制 Armature 修改器 → modifier_apply → 删除重建全部形态键」整套逻辑，改为 `_bake_pose_into_vertices()`：
  1. 形态键 value 归零（**跳过 Basis**，见下）→ 非 Armature 修改器 `show_viewport=False`
  2. `view_layer.update()` 后重新取 depsgraph，`evaluated_get().to_mesh()` 读局部坐标
  3. 恢复 value / 修改器开关 → 写回 Basis（无形态键则写 `mesh.vertices`）
  4. 之后照旧 `armature_apply()`，非手臂骨姿态靠 `matrix_basis` 备份/恢复
- 异常路径 `finally` 统一调用 `_restore_bake_states()`（幂等），不会再残留临时修改器。
- 兼容性修复 1：Blender 4.5 的 `PoseBone` **没有** `select`（5.x 才有，4.5 是 `Bone.select`），原代码 `pose_bones[n].select = True` + `rot_clear()` 在 4.5 直接报错。改为直接 `pose_bones[n].matrix_basis = Matrix.Identity(4)`，跨版本通用。
- 兼容性修复 2：`bone_utils._restore_shape_keys()` 重建 Basis 后没恢复 `value`，4.5 新建 Basis 默认 0（5.x 默认 1），导致 4.5 上 Basis value 从 1 变 0。补 `basis.value = backup[0]['value']`，此修复对所有调用 `apply_armature_transforms` 的操作生效。
- 验证脚本：`tools/apose_operator_verify.py`（真实工程端到端，直接调 `bpy.ops.object.convert_to_apose`）、`tools/apose_operator_smoke.py`（最小场景，覆盖 4.0/4.2 这类读不了 4.5 blend 的版本）。
- 结果：最小场景 4.0.2 / 4.2.8 / 4.5.5 / 5.0.1 / 5.2.0 全部 6/6；真实工程 JP(TESTMIKU1) 4.5/5.0/5.2 与 EN(TESTMIKU) 5.2 全部 7/7。检查项含 operator 返回、Basis 改变、姿态归零、修改器栈无 `_copy` 残留、形态键数量与 value、烘后不跳变。
- 注意：日文工程本来就是 A-Pose（上臂仰角 -36°），Basis 不变是正确行为；验证脚本用 `already_apose` 区分。
- 踩坑：`bpy.ops.object.shape_key_add()` 返回的是 `{'FINISHED'}` 集合，不是新建的形态键，需从 `mesh.data.shape_keys.key_blocks[-1]` 取；调用前必须先把 mesh 设为 active。
