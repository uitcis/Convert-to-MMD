# Convert-to-MMD 项目长期约定

## 发版流程（用户 2026-11-27 确认）

Gitee 发行流水线以 `GITEE_COMMIT_MESSAGE` 作为 tag 名，**提交说明必须是纯版本号**（如 `V1.5`），带描述文字会生成非法 tag 导致发行失败。

因此一次发版通常需要**两次提交**：

1. **提交更新**：正常提交说明，包含代码 / 功能 / CHANGELOG 内容变更。
2. **提交发行触发**：单独一次提交，提交说明**只有纯版本号**（如 `V1.5`），用于打 tag 并触发 `.workflow/发行.yml`。

- 版本号两套编号互不干扰：`__init__.py` 的 `bl_info.version` 长期为 `(2, 6)`；发版标签走 CHANGELOG 的 `1.x`（当前 V1.5）。不要擅自同步。
- CHANGELOG 约定：**每次发版只保留当前版本**，旧条目不要堆叠。
- 流水线会从 CHANGELOG 解析版本，与提交说明的 tag 名对应；两者都要写对。
- 历史教训：V1.5 首次提交写成 `V1.5 自动骨骼映射...`，流水线把整句当 tag 名，空格导致失败；用 `git commit --amend -m "V1.5"` + `--force-with-lease` 强推修正后才发行成功。
