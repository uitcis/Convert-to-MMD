## Convert-to-MMD 插件修复（IK + 肩P骨骼）

两个 Bug 共同根因：**Blender 编辑模式（EDIT）下 `pose.bones` 不随 `edit_bones` 更新，是进入编辑模式前的快照**。

1. `operators/add_shoulder_p_bones_operator.py` — 修复 `KeyError: '右肩C' not found`（原 line 133）：
   - 在创建骨骼后、访问 `pose.bones` 前先 `mode_set(mode='OBJECT')` 同步姿态数据
   - `pose.bones[c_name]` 改为 `.get()` + 空值跳过，避免异常中断导致模式残留
2. `operators/ik_operator.py` — 修复 IK 约束不生效：
   - 同样改为：编辑模式创建 IK 骨骠 → 退出到 OBJECT 模式 → 再添加约束（此时 subtarget 如 `左足ＩＫ` 已存在于姿态数据，约束可正确解析）
   - 新增 `clear_ik_constraints()`：重复执行前清除旧 "IK"/"mmd_ik_limit_override"/"mmd_ik_target_override" 约束，避免叠加冲突
   - 增加 `required_pose_bones` 同步校验，失败时报错并恢复原模式

经验：本插件所有"编辑模式建骨 + 添加姿态约束"的操作符都必须遵循「EDIT 建骨 → OBJECT 同步 → 加约束」顺序。

## 追加修复：mode_set 枚举不兼容（TypeError: enum "EDIT_ARMATURE" not found）

- 根因：`context.mode` 返回 `'EDIT_ARMATURE'`（带对象类型后缀的上下文枚举），而 `bpy.ops.object.mode_set` 只接受 `'OBJECT'/'EDIT'/'POSE'`。此前恢复路径从未触发所以未暴露；上一轮修复后中途切到 OBJECT，恢复路径触发即崩溃
- 修复：`bone_utils.py` 新增 `context_mode_to_mode_set()` 辅助函数（EDIT_ARMATURE→EDIT，WEIGHT_PAINT 等退回 OBJECT）
- 应用到 4 个用 `context.mode` 记录模式的文件：`ik_operator.py`（3 处恢复点）、`add_shoulder_p_bones_operator.py`、`rename_bones_operator.py`、`tools/adjust_bone_rolls_operator.py`
- `merge_bones`、`correct_bones`、`utility_operators`、`auto_connect` 用的是 `obj.mode`（兼容 mode_set），无需修改
- 规范：新操作符恢复模式时统一用 `restore_mode = bone_utils.context_mode_to_mode_set(context.mode)`，或直接用 `obj.mode` 记录

## 设置骨骼扭转（calculate_bone_rolls）规则（用户精确规格，已重写）

`bone_utils.calculate_auto_bone_roll(edit_bones, armature_obj)` 当前规则：
- **局部轴范围**（手臂链 + 扭转骨 + 手指），命中 `_LOCAL_AXIS_HINTS = ("肩","腕","ひじ","手首","捩","親指","人指","中指","薬指","小指")`：
  - 左侧（名含 `.L` 或以「左」开头）→ `align_roll(世界+Z)`（Shift+N 全局 +Z）
  - 右侧（名含 `.R` 或以「右」开头）→ `align_roll(世界-Z)`（Shift+N 全局 -Z）
- **范围外所有骨骼**（躯干/头/腿/重心/IK/末端虚骨 等）：**不再跳过，全部处理**
  - `head 世界Z > tail 世界Z`（头高于尾）→ `align_roll(世界+Y)`
  - 否则 → `align_roll(世界-Y)`
  - 几何理由：竖直骨(平行Z)不能用±Z算 roll（退化），改用 ±Y 才稳定。
- 世界轴按骨架 `matrix_world.to_3x3().inverted()` 转到骨架局部空间（`inv_rot @ 世界轴`），骨架被旋转时仍保持「全局」语义。
- 零长度骨骼 `continue` 跳过；`ReferenceError`（骨骼已移除）忽略。
- **返回 `(adjusted, local_count, fallback_count)`**（三元组）。
- 辅助函数 `_is_left/_is_right/_is_local_axis_bone` 替代旧 `_classify_mmd_bone`；已删除 `_GLOBAL_AXIS_HINTS` 与右肩 180° 特例。

关键变更（相对上一版）：① `肩` 从「全局轴(右肩180°)」改为「局部轴(±Z)」；② 取消"未识别→跳过/未找到MMD骨骼警告"逻辑，所有骨骼都参与；③ 调用方 `adjust_bone_rolls_operator.py` 须解包三元组，报告改为 `局部轴(±Z) N 根 / 其余(±Y) M 根`。

**查表固定值法已彻底移除（用户要求）**：删除 `bone_utils.py` 中 `DEFAULT_ROLL_VALUES`（_VERTICAL_ZERO/_FINGERS_ZERO/_LEFT_ARM/_RIGHT_ARM/_LEFT_SHOULDER/_RIGHT_SHOULDER 全套 0/45/135/180° 表）、`set_roll_values()` 函数、`AUTO_LOCAL_AXIS_*` 四个死常量，以及 `from math import radians` import（仅 set_roll_values 用到）。`rename_bones_operator.py:83` 与 `complete_bones_operator.py:246` 改为调用 `bone_utils.calculate_auto_bone_roll(edit_bones, armature_obj=obj)`（几何/按名算法，与「设置骨骼扭转」按钮同一套）。全项目已无 `DEFAULT_ROLL_VALUES`/`set_roll_values`/`AUTO_LOCAL_AXIS` 引用，四文件 py_compile 通过。

注意：`calculate_auto_bone_roll` 在 `complete_bones_operator` 中已移到 `connect_finger_bones` **之后**调用（用户要求），使手指 roll 基于连接后的真实头尾方向计算。done。

**新增 MMD 检测守卫（用户要求）**：`bone_utils` 增加 `_MMD_GLOBAL_HINTS`（センター/グルーブ/腰/上半身/下半身/首/頭/足/ひざ/足首/つま先/足先/腿/全ての親/操作中心）+ `_is_mmd_bone()` + `count_mmd_bones(edit_bones)`。
`adjust_bone_rolls_operator` 在处理前调用 `count_mmd_bones`，若 ==0 则 `report WARNING "未检测到MMD骨骼：非MMD骨骼无作用，操作已跳过。"` 并 `return {'CANCELLED'}`（先恢复模式）。用于区分"真·非MMD骨架"与"MMD骨架"，避免旧版乱报"没有MMD骨骼"的问题复发。
