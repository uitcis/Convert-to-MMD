## mmd_tools roll 机制调研 + calculate_auto_bone_roll 二次重写（极简夹角版）
- 用户场景：从其他模型转换到 MMD 结构，源骨架**无 PMX localCoordinate**，问"能否不靠名称决定 roll"。
- mmd_tools 机制确认（本地 5.1 源码）：三层优先级（importer.py:259-263）：① `localCoordinate` 非空 → `update_bone_roll`（数据驱动，与名称无关）；② 否则名称命中自动局部轴名单 → `update_auto_bone_roll`（几何）；③ 否则 roll 保持 0。自动局部轴名单（bone.py:45-47）**只有臂/捩/肩P/ダミー/手指，没有腿**；坐标轴直接用世界轴（假设 Z-up 摆正），无方向推断、无拓扑、无查表。
- **重要发现（纯 Python 数学模拟验证）**：mmd_tools `update_auto_bone_roll`+`update_bone_roll` 对"无 localCoordinate 的水平臂"是**左右不对称**的——左腕 `align_roll(+Y)`（X 朝前）、右腕 `align_roll(-Y)`（X 朝后）。真实 MMD 模型右臂正确是因为带 localCoordinate 绕过了此兜底路径；直接 `align_roll(法线)` 更错（左腕也朝后，因 get_axes 的 .xzy 交换+相邻轴选择改变符号）。故**转换场景不能复刻该公式**，用户需求是"左右臂 X 都朝前"。
- 最终实现（`bone_utils.calculate_auto_bone_roll` 重写为极简夹角版，零名称零拓扑）：竖直骨（`|y·up|>cos25°`，覆盖躯干/头/颈/腿）`roll=0`（X 轴朝右）；其余骨（臂/肩/腕/手指）`align_roll(front=+Y)`（X 轴朝前）。假设 Z-up 摆正、正面朝 +Y（与 mmd_tools 相同假设）。`AUTO_LOCAL_AXIS_*` 常量保留未删（已无引用）；`from mathutils import Vector` 新增，`import math` 移除。
- 教训：Blender 骨骼 roll 与 align_roll 的世界方向换算受骨骼方向影响，手推易错；关键判断用"目标世界方向"而非"roll 角度值"。lint 0 错误。
- 修复后验证（纯 Python 模拟 Blender 语义：roll=0 竖直骨 X=(1,0,0)；align_roll(front)=front 投影到垂直 y 平面）：标准 T-pose 下 躯干/头/左右腿/脚踝 → X=+X（右）OK；左肩/右肩/左右腕/左右手首 → X=+Y（前）OK 且左右对称；朝前延伸的手指（y·front>0.99）跳过保持原 roll。修复前的右腕 -Y（后）问题已消除。未在真实 Blender 中实测。
